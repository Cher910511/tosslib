# 软件治理国标评分需求文档

## 1. 需求背景与目标

### 1.1 需求背景

随着开源软件在业务系统中的深度应用，开源组件引入的安全、合规与供应链风险日益突出，亟需一套可量化、可执行的开源软件治理评估机制。当前软件治理流程覆盖「软件获取 → 引入选型 → 软件技术评估 → 治理成果验收 → 软件入库」五个阶段，但选型评估主要依赖人工经验与零散工具，缺乏统一、客观的量化评分标准，难以支撑规模化、常态化的准入与风险管理。

### 1.2 需求目标

建设软件治理国标评分能力，依据 GB/T 47020 选型评估指标体系，对开源软件的**代码技术安全、合法合规、供应韧性**三大维度共 **33 项指标**（基线 15 项 + 增强 18 项）进行逐项量化评分，并自动汇总为国标评分（0-100 分）。通过自动化扫描与人工评定相结合的方式，为软件准入、选型决策与风险处置提供客观、可追溯的量化依据，并将评分结果嵌入治理流程，作为阶段推进的必要条件。

## 2. 功能概述

软件治理页面（`AdminGovernanceView.vue`）按五阶段流程管理开源软件的全生命周期：

| 步骤 | 阶段 | 关键操作 | 前置条件 |
|------|------|---------|---------|
| 1 | 软件获取 | 获取软件列表 / Excel 导入 / 下载模板 | — |
| 2 | 引入选型 | 备份软件源码 | 选中软件 |
| 3 | 软件技术评估 | 启动扫描（SCA / 版权 / 恶意代码）、国标评分 | 备份成功 |
| 4 | 治理成果验收 | 批量审核通过 / 不通过 | 评估完成 |
| 5 | 软件入库 | 批量入库 / 单个入库 | 评审通过 |

页面顶部 KPI 条展示各阶段待处理数量：总计 / 待备份 / 待评估 / 待评审 / 待入库 / 已入库。

## 3. 国标评分功能详述

### 3.1 评分入口

- **步骤 3（软件技术评估）**：表格「国标评分」列点击软件名所在行的评分值（或操作列「评分」按钮），打开评分弹窗；
- **步骤 5（软件入库）**：表格「国标评分」列点击评分值，可打开评分弹窗（**见 5.4 未闭环问题**）。

### 3.2 评分弹窗（IndicatorScoreDialog）

| 区域 | 说明 |
|------|------|
| 头部 | 标题「指标评分」+ 软件名称/版本 + GB/T 47020 说明 |
| 汇总条 | 国标评分总分（0-100，实时汇总）+ 已评 X/33 项 + 基线/增强小计 + 「一键自动评分」按钮 |
| Tab 切换 | 基线指标 / 增强指标，带各 Tab 指标数 |
| 筛选 | 「只看未评分」复选框 + 未评数提示 |
| 指标表格 | 列：指标 / 说明（含要求等级、范围、工具）/ 权重 / 评分控件 / 得分贡献 |
| 底部 | 操作提示 + 取消 / 保存评分 |

### 3.3 指标体系（govIndicators.js）

33 项指标分为**基线**（强制性，权重合计 66%）与**增强**（推荐性，权重合计 34%）两级，每项指标配置：

- **级别**：基线 / 增强；
- **分类**：代码技术安全 / 合法合规 / 供应韧性；
- **分组**：如超危漏洞、漏洞密度、许可证合规、社区支持等；
- **要求等级**：强制性 / 推荐性；
- **权重**：百分比（全表合计 100）；
- **评分范围**：0-10 或 0或10；
- **计算公式**：如 `w*(1 - min(n/8, 1))`；
- **测评方法**：文字描述；
- **打分参考**：边界说明；
- **capable**：是否具备自动评分能力（18 项自动 / 15 项手动）。

### 3.4 评分规则

1. 每个指标原始分 s ∈ [0,10]；
2. 加权贡献 = 权重(%) × s / 10；
3. 国标评分（0-100）= Σ(权重 × s / 10)，权重合计 100；
4. 评分方式四类：
   - **pass**：合格 ? 10 : 0（二元判定）；
   - **lts**：LTS ? 10 : 5；
   - **score**：手动打分 0-10；
   - **formula**：输入参数按公式自动计算 0-10（如超危漏洞数 n、漏洞密度 d、修复天数 t）。

### 3.5 评分数据流

1. 打开弹窗 → `init()`：加载已保存评分（`item.indicatorScores`）；无则对 capable 指标自动预填（`autoScoreRecord`），其余置空；
2. 用户操作：pass/lts 点选、score 手动输入、formula 输入参数（实时联动得分）；
3. 一键自动评分（`runAutoScore`）：对 capable 指标按扫描数据重新打分（**见 5.5 未闭环问题**）；
4. 保存（`saveScore`）：写入 `item.indicatorScores`，计算 `nationalScore`，记录日志「国标评分完成：X 分」。

## 4. 各阶段功能逻辑

### 4.1 软件获取（步骤 1）

- 获取软件列表 / Excel 导入（.xlsx/.xls/.csv）/ 下载导入模板；
- 勾选软件后「引入选型」推进至步骤 2（不校验其他条件）。

### 4.2 引入选型（步骤 2）

- 「备份软件源码」：选中且备份状态为「待备份」的软件进入「备份中」，2 秒后置为「备份成功」并生成镜像仓库地址，写入日志；
- 推进至步骤 3：仅推进 `backupStatus === '备份成功'` 的条目。

### 4.3 软件技术评估（步骤 3）

- 「启动扫描」：并行模拟 SCA / 版权 / 恶意代码三条进度条，全部 100% 后置 `assessStatus = '评估完成'`，记录日志；
- 「国标评分」：打开评分弹窗（见第 3 章）；
- 推进至步骤 4：仅推进 `assessStatus === '评估完成'` 的条目（**不校验是否已完成国标评分**）。

### 4.4 治理成果验收（步骤 4）

- 批量审核通过 / 不通过（需填写审核意见），或单个「审核」弹窗提交（记录审核历史）；
- 「加入待入库」：推进 `reviewStatus === '评审通过'` 的条目至步骤 5（待入库）。

### 4.5 软件入库（步骤 5）

- 批量入库 / 单个入库：将 `warehouseStatus` 置为「已入库」；
- 已入库软件隐藏「移除」操作；
- KPI「已入库」计数 = `currentStep === 5 && warehouseStatus === '已入库'`。

## 5. 逻辑闭环问题及修复记录

> 以下问题基于当前前端实现（mock 数据）逐条核对得出，均已闭环修复。

### 5.1 评分未纳入流程推进校验（已修复）

**问题**：`advanceToStep()` 从步骤 3 推进到步骤 4 仅校验 `assessStatus === '评估完成'`，不校验国标评分是否完成。软件可以完全不做国标评分就推进到验收、入库阶段，评分成为「可选动作」而非准入必要条件。

**修复**：在 `advanceToStep()` 步骤 3 → 4 分支与 `selectedAdvanceableCount` 中均增加评分校验：需 `assessStatus === '评估完成' && nationalScore != null` 方可推进；未评分条目不进入可推进数量统计。

### 5.2 步骤 5（入库）仍可修改评分（已修复）

**问题**：步骤 5 表格的「国标评分」列绑定 `openScoreDialog`，待入库/已入库软件均可再次打开评分弹窗修改分数，且无重新评审流程。

**修复**：步骤 5 的评分列改为只读展示（`.gov-score-readonly`），不再绑定评分弹窗，入库后评分不可修改。

### 5.3 入库前不校验评分完整性（已修复）

**问题**：`confirmWarehouse()` / `singleWarehouse()` 对选中项直接置为「已入库」，不校验 `nationalScore` 是否为空，可保存全空记录。

**修复**：`confirmWarehouse()` / `singleWarehouse()` 入库前校验 `nationalScore != null`；未评分的软件不入库，并写入日志「未完成国标评分，无法入库」。

### 5.4 评分入口重复、阶段不一致（已修复）

**问题**：「国标评分」入口同时存在于步骤 3 与步骤 5，步骤 4 验收无评分入口，同一软件可在不同阶段重复评分。

**修复**：评分入口仅在步骤 3（软件技术评估）提供；步骤 4 审核弹窗展示评分结果作为验收依据；步骤 5 只读展示评分。

### 5.5 一键自动评分会覆盖手动评分（已修复）

**问题**：`runAutoScore()` 注释声明「不覆盖已手动填写的指标」，但实现无条件覆盖全部 capable 指标，用户手动评分会被静默覆盖。

**修复**：新增 `manuallyScored` 集合记录用户手动评分（pass/lts/score/formula 四个入口）及已保存的评分；`runAutoScore()` 跳过 `manuallyScored` 中的指标，仅对未手动评分的 capable 指标重新打分。

### 5.6 评分与验收（步骤 4）无联动（已修复）

**问题**：审核弹窗仅记录「通过/不通过 + 意见」，不展示国标评分结果，评分不参与验收判断。

**修复**：审核弹窗（`review-modal`）新增「国标评分」展示区（`.review-score`），展示评分值；未评分时给出提示「该软件尚未完成评分，建议先评分再验收」。

### 5.7 移除操作无任何校验（已修复）

**问题**：`removeItem()` 无二次确认、无审计记录、无恢复机制。

**修复**：新增移除确认弹窗（二次确认）；`confirmRemove()` 移除前写入软件日志并在 `removedAudit` 审计列表留痕（时间/软件名/版本/动作）。

### 5.8 备份/扫描为前端模拟（暂缓，待后端对接）

**说明**：备份成功、扫描进度、镜像地址均为 `setTimeout` 模拟，无真实接口；`assessStatus` 推进依赖模拟完成。该问题需与后端契约对齐后闭环，前端已预留状态流转结构（`backupStatus` / `assessStatus` / 进度字段），当前不阻塞页面功能。

### 5.9 评分弹窗参数无校验上限（已修复）

**问题**：formula 类指标的参数输入框未阻止超出 `min/max` 的值（如漏洞数输入负数），用户可输入越界值。

**修复**：`onParamInput()` 按参数定义 `min/max` 收敛越界输入，再参与公式计算。

## 6. 验收标准（已达成）

1. 步骤 3 完成扫描后，未评分软件无法推进至步骤 4；
2. 步骤 5 软件评分只读，无法修改；
3. 已入库软件无评分变更入口；
4. 一键自动评分不覆盖用户手动评分；
5. 审核弹窗展示国标评分与未评分提示；
6. 入库操作校验评分完整性（未评分不入库并留日志）；
7. 移除操作二次确认并留审计记录。
