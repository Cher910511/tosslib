# OpenAPI 开放平台 — 需求文档

版本：v2.0 | 2026-07-15

---

## 1. 概述

### 1.1 产品背景

可信开源代码库已完成软件组成分析、漏洞检测、许可证合规等核心功能的产品化，但现有能力仅限 Web 页面操作，无法被外部系统（CI/CD 流水线、IDE 插件、内部治理平台）直接调用。OpenAPI 开放平台旨在将核心治理能力以标准化 RESTful 接口开放，使客户能够将软件供应链安全检测集成到自有研发流程中。

### 1.2 产品目标

1. **能力开放**：将 SCA 扫描、漏洞预警、SBOM 生成、恶意代码检测、AI 助手等核心能力以 API 形式开放
2. **易集成**：统一认证（Bearer Token）、统一响应格式、统一错误码
3. **安全可控**：API Key 认证机制，支持密钥创建、删除，全链路 HTTPS（TLS 1.3）
统一格式的api文档

### 1.3 目标用户

| 用户角色 | 场景 | 诉求 |
|---------|------|------|
| DevOps 工程师 | CI/CD 流水线集成 | 流水线步骤中自动触发 SCA 扫描和漏洞检测 |
| 安全工程师 | 自动化安全审计 | 批量查询组件漏洞、恶意代码检测 |
| 研发经理 | 项目治理管控 | 通过 API 获取团队项目治理数据 |
| 平台集成商 | 集成到自有平台 | 通过统一接口对接内部管理系统 |

### 1.4 范围

#### 包含

- 11 个接口的定义与实现（SCA 扫描、漏洞预警、SBOM 生成、AI 助手、许可证查询、恶意代码检测、软件搜索、软件详情、组件搜索、组件详情、报告生成）
- API Key 认证系统（密钥创建、删除、管理）
- 通用错误码体系
- 接口文档（独立 OpenAPI 文档页）

#### 不包含（后续迭代）

- Webhook 事件回调
- OpenAPI 3.0 规范文档导出（Swagger UI）
- SDK 客户端库
- 按量计费与账单系统

## 2. 接口清单

### 2.1 SCA 扫描

**接口目的**：用户上传软件包文件（zip/jar/war/tar.gz/容器镜像），系统自动识别组件清单、依赖关系、漏洞信息、许可证合规等，返回完整的软件分析报告。这是平台最核心的接口，替代了人工在 UI 上逐个填写字段、上传文件的繁琐流程。

**设计思路**：SCA 扫描与平台 UI 上的「新增软件」流程完全解耦。API 用户只需传一个文件，不需要关心平台上的软件名称、版本、语言等字段，系统自动识别。扫描结果包含版本、集成风险、主语言、开发商、许可证列表、代码量、漏洞数、软件生命力、EOL 日期、依赖关系、SBOM 链接、漏洞列表、Copyright 报告等完整信息。

**文件上传**：支持 zip/jar/war/tar.gz 以及容器镜像，上限 200MB。

**响应特点**：数据量大，一次返回完整扫描结果，不采用异步轮询模式。

### 2.2 漏洞预警查询

**接口目的**：查询平台已关注软件的漏洞预警信息。与传统的 CVE 查询不同，该接口返回的是「预警」而非原始漏洞列表——每条预警自带处理状态（待处理/已解决/已忽略）、置信度、预警时间，并包含完整的漏洞详情和处置建议。

**设计思路**：预警信息与平台关注的软件版本绑定，当监测到新的 CVE 时自动生成预警。支持按严重等级、处理状态、预警时间范围进行筛选，方便安全工程师快速定位需要处理的漏洞。预警通知内容包含完整的漏洞信息模板，可直接用于邮件或即时通讯通知。

**筛选维度**：软件包名、严重等级、处理状态、预警时间范围、分页。

### 2.3 SBOM 生成

**接口目的**：根据 SCA 扫描结果生成软件物料清单（SBOM），返回组件列表。格式完全遵循 SPDX/CycloneDX 标准的组件字段结构。

**设计思路**：与 SCA 扫描接口联动，传入 scan_id 即可获取该扫描的完整组件清单。每条组件包含序号、group_id、package_name、version、语言、PURL（Package URL）。不提供格式转换功能，直接返回 JSON 结构，方便下游系统直接消费。

**前置条件**：需要先调用 SCA 扫描接口获取 scan_id。

### 2.4 AI 智能选型助手

**接口目的**：提供智能问答能力，围绕开源软件全生命周期为用户提供支持，包括开源软件发现与选型、风险评估、漏洞与安全合规核查、代码审查等。

**设计思路**：采用两步响应模式——先同步创建会话并返回会话 ID，再通过 SSE（Server-Sent Events）流式推送 AI 的推理过程和最终回答。流式事件包含 reasoning（思考过程）、text（最终文本）、tool_batch/tool_start/tool_result（工具调用）、tokens（用量统计）、done（完成信号）等多种类型，前端可基于这些事件实现打字机效果和工具调用可视化。

**SSE 事件类型**：reasoning / text / tokens / tool_batch / tool_start / tool_result / tool_output / done。

### 2.5 开源合规查询

**接口目的**：查询开源许可证的详细信息，包括许可证类型、OSI 批准状态、允许的行为、限制条款及必须履行的义务。

**设计思路**：这是一个纯查询接口，传入许可证名称即可获取完整的许可证合规信息。与之前的设计不同，不再提供风险评估和报告生成功能，而是聚焦于许可证本身的属性查询。返回结果包含许可证名称、版本、类型、批准状态、permissions（允许的）、limitations（受限的）、obligations（必须的）三组属性列表，以及许可证的完整描述。

**典型场景**：开发者在引入一个新的开源组件前，先查询其许可证的合规要求，判断是否适合商业使用。

### 2.6 恶意代码检测

**接口目的**：上传二进制文件，通过静态分析与行为检测技术识别潜在恶意代码、后门程序及可疑行为。

**设计思路**：与 SCA 扫描类似，用户上传文件即可检测，不需要在平台预创建任何记录。检测结果包含文件的 SHA256 哈希、恶意分类（如 Java）、恶意行为类型（如恶意行为）、子类型（如木马下载执行）、威胁等级、置信度、检测结果描述以及关键检测日志。

**关键检测日志**：包含匹配的规则名称和对应的代码行号，方便安全工程师定位具体问题。例如 `->Rule_D_HTTP_HttpURLConnection` 表示检测到 HTTP URL 连接行为，并列出触发的代码行。

**文件格式**：支持 jar/zip/tar.gz/exe/apk 等常见二进制格式，上限 200MB。

### 2.7 软件搜索

**接口目的**：搜索平台中的软件列表，支持按名称、版本、语言、漏洞状态、行业分类、版本火车等多维度检索。

**设计思路**：这是一个面向平台数据资产的搜索接口，帮助用户从平台已有的软件库中快速定位目标软件。搜索结果包含软件 ID、版本 ID、名称、开发商、主语言、发布日期、行业分类、漏洞数、评分、生命周期阶段、出入库状态等字段。

**筛选维度**：软件名称、版本、语言、有无漏洞、行业分类、版本火车、分页。

### 2.8 软件详情

**接口目的**：查询指定软件的详细信息，包括基本信息、版本信息、生命周期、评分、下载地址、源码仓库等。

**设计思路**：与软件搜索配合使用，先搜索获取 software_id，再查询详情获取完整信息。详情数据量较大，包含软件级信息（名称、描述、开发商、行业分类、评分、生命周期）和版本级信息（版本名称、发布日期、许可证、漏洞数、Star/Fork/Watch 数、Scorecard 评分、关键性评分、下载地址、签名文件、源码仓库等）。

**典型场景**：CI/CD 流水线中在引入一个软件前，先查询其详情评估安全性和活跃度。

### 2.9 组件搜索

**接口目的**：搜索平台中的组件列表，支持按组件名称、版本、语言、版本火车等多维度检索。

**设计思路**：与软件搜索类似，但面向的是组件粒度。组件是附属于软件的更细粒度单元，包含 group_id、artifact_id 等 Maven 风格的信息。搜索结果包含组件 ID、名称、版本、component_code、group_id、artifact_id、语言、许可证、出入库状态等。

**筛选维度**：组件名称、版本、语言、版本火车、分页。

### 2.10 组件详情

**接口目的**：查询指定组件的详细信息，包括组件基本信息、许可证、源码地址、所属软件等。

**设计思路**：与组件搜索配合使用，先搜索获取 component_id，再查询详情。详情包含组件名称、版本、group_id、artifact_id、语言、许可证、描述、首页、源码仓库、代码行数、所属软件 ID、出入库状态等。

### 2.11 报告生成

**接口目的**：上传软件包文件，自动生成 PDF 格式的安全检测报告，包含组件清单、漏洞分析、许可证合规等完整信息。

**设计思路**：与 SCA 扫描类似，上传文件即可生成报告，但返回的是 PDF 下载链接而非结构化数据。适合需要将检测结果以文档形式存档或分发的场景。报告下载链接有效期为 24 小时。

**文件格式**：支持 zip/jar/war/tar.gz 等，上限 200MB。

## 3. 全局约束

### 3.1 通信协议

| 项目 | 约束 |
|------|------|
| 协议 | HTTPS 强制，TLS 1.3 |
| Base URL | `https://api.tosslib.com/v1` |
| 响应格式 | JSON（统一结构） |
| 文件上传 | `multipart/form-data` |

### 3.2 认证鉴权

所有接口均通过 `Authorization: Bearer sk_live_xxxx` 请求头进行认证。API Key 在平台控制台「密钥管理」页面创建，格式为 `sk_live_` + 40 位随机小写字母数字。密钥被删除后立即失效。

### 3.3 权限模型（Scope）

API Key 绑定 Scope 权限范围，控制密钥可访问的接口：

| Scope | 可访问接口 | 适用场景 |
|-------|-----------|----------|
| `read` | 软件搜索、软件详情、组件搜索、组件详情、许可证查询、漏洞预警查询 | CI 流程中仅查询已有结果 |
| `scan` | SCA 扫描、SBOM 生成、恶意代码检测、报告生成 | 自动化扫描流水线 |
| `admin` | 全部接口 + AI 助手 | 平台集成商 |

### 3.4 API Key 管理功能

| 功能 | 说明 |
|------|------|
| 创建密钥 | 用户输入名称，系统生成 `sk_live_` + 40 位随机字符串 |
| 查看密钥 | 列表展示掩码后的密钥（前 8 位 + 后 4 位可见） |
| 复制密钥 | 创建时弹窗展示完整密钥，用户可手动选中复制，关闭后不可再次查看 |
| 删除密钥 | 删除后密钥立即失效，使用该密钥的请求返回 401 |
| 编辑名称 | 支持修改密钥名称，便于管理 |

### 3.5 统一响应结构

所有接口遵循统一的响应格式：

```json
{
  "code": 200,
  "error_name": null,
  "msg": "success",
  "trace_id": "uuid",
  "data": { ... }
}
```

分页接口统一使用 `page_num` / `page_size` / `total` / `page_count` / `content[]` 结构。

### 3.6 通用错误码

| code | HTTP | 含义 |
|------|------|------|
| 200 | 200 | 成功 |
| 400 | 400 | 请求参数不合法 |
| 401 | 401 | 未携带或无效的 API Key |
| 404 | 404 | 资源不存在 |
| 500 | 500 | 服务内部错误 |

## 4. 接口依赖关系

```
SCA 扫描 ────→ SBOM 生成（依赖 scan_id）
SCA 扫描 ────→ 报告生成（可独立使用，直接上传文件）
软件搜索 ────→ 软件详情（依赖 software_id）
组件搜索 ────→ 组件详情（依赖 component_id）
```

其余接口均为独立接口，无前置依赖。

## 5. 与 UI 的关系

| 接口 | 与 UI 的关系 |
|------|-------------|
| SCA 扫描 | 完全独立，API 直接传文件，不经过平台新增流程 |
| 漏洞预警 | 数据来源于平台关注的软件，但 API 查询结果独立 |
| SBOM 生成 | 依赖于 SCA 扫描结果 |
| AI 助手 | 独立能力，与平台 AI 助手共享同一后端 |
| 许可证查询 | 数据来源于平台许可证库 |
| 恶意代码检测 | 完全独立，API 直接传文件 |
| 软件/组件搜索 | 数据来源于平台软件库/组件库 |
| 软件/组件详情 | 数据来源于平台软件库/组件库 |
| 报告生成 | 完全独立，API 直接传文件生成 PDF |
