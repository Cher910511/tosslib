## 1. 需求背景

当前登录用户进入系统后统一落至功能列表式首页，存在以下问题：

- **无角色化落地页**：组织管理员与普通成员看到的页面完全一致，未体现两者职责差异（管理员负责组织治理与版本火车管理，成员负责日常使用）。
- **数据可见范围不清晰**：普通成员仅可查看所在组织**已发车**版本火车内的软件与组件，管理员可查看全量并具备治理能力；现有首页未做权限区分，用户易触达无权限内容。
- **缺乏组织维度总览**：管理员缺少一屏掌握组织治理全貌的入口，版本火车状态、风险预警、成员情况等分散在多个子页面。
- **使用路径冗长**：成员需从首页逐级点击才能到达已发车软件、订阅项目、下载记录等常用内容，效率低。
- **多组织场景缺失**：少数用户同时属于多个组织，缺乏组织隔离与切换能力。

## 2. 需求目标

对标平台现有页面样式规范，建设**按角色差异化渲染的独立用户工作台**：

1. **角色差异化**：组织管理员进入「治理视角」工作台，普通成员进入「使用视角」工作台，内容、操作、数据范围严格区分。
2. **组织隔离**：所有数据按「当前用户 + 当前组织」维度隔离；单组织用户直接展示，多组织用户支持顶部切换，主组织默认在前。
3. **权限正确**：普通成员仅可见已发车软件/组件及关联预警，无权限数据不展示；点击无权限内容时提示「暂无权限查看该软件/组件，请联系组织管理员」。
4. **信息密度高**：以多卡片、多数据类型网格承载 KPI、版本火车状态、风险预警、软件/组件列表、订阅项目、许可证合规、下载记录、最近更新、快捷入口等。
5. **路径最短**：登录后默认进入工作台（根路径自动跳转），右上角提供工作台图标入口。
6. **可演进**：角色与组织判断逻辑预留真实登录态接入点，后续替换为后端会话数据即可复用布局。

## 3. 角色定义与权限边界

| 角色 | 定位 | 数据范围 | 管理操作 |
|---|---|---|---|
| 组织管理员 | 治理者 | 全量（含未发车） | 版本火车发车/上下架、成员权限、软件出入库等 |
| 普通成员 | 使用者 | 仅已发车版本火车内 | 无（仅查看/下载） |
| 超级管理员 | 平台运维 | 全站 | 全量管理（本期不纳入工作台，沿用既有入口） |

## 4. 工作台入口与进入条件

| 场景 | 行为 |
|---|---|
| 用户登录后访问根路径 `/`（裸域名） | 自动重定向至 `/software/workbench`，进入工作台 |
| 用户在其他页面 | 点击右上角工作台图标返回工作台 |
| 侧边栏 | 不新增工作台入口，保持现有导航结构不变（工作台通过根路径与右上角图标进入） |
| 当前用户角色 | 由登录态决定：组织管理员 → 治理视图；普通成员 → 使用视图 |

## 5. 功能需求

### 5.1 组织管理员工作台（治理视角）

**定位**：一屏掌握组织治理全貌。

| 模块 | 内容 |
|---|---|
| KPI 指标行（10 卡片） | 使用中软件/组件、下架软件/组件、本周新增预警、待发车/已发车/已过期火车、待处理预警、管理员数（各带周/月趋势） |
| 版本火车状态 | 状态堆叠条（待发车/已发车/已过期）+ 图例 |
| 待办提醒条 | 待发车、待处理预警、待评审软件等，可跳转版本火车 |
| 风险等级分布 | 环形图（超危/高危/中危/低危） |
| 漏洞软件排行 Top10 | 软件名/版本/漏洞数，支持筛选已下架 |
| 漏洞组件排行 Top10 | 组件名/版本/漏洞数 |
| 许可证合规分布 | 环形图（Apache/MIT/BSD/GPL 等） |
| 组件主语言分布 | 环形图（Java/JS/C/Python/Go/Rust 等） |
| 厂商/供应商 Top10 | 横向条形图 |
| 近 30 天预警趋势 | 折线图 |
| 近 30 天发车/下架趋势 | 双折线图 |
| 软件与组件概况 | 柱状图（使用中/已下架） |
| 成员与角色统计 | 管理员/普通成员占比 + 近 7 天新增趋势 |
| 最新预警 | 5 条列表，可跳转预警页 |
| 最近操作日志 | 10 条时间线（发车/上下架/预警/成员变更） |

### 5.2 普通成员工作台（使用视角）

**定位**：仅展示所在组织已发车版本火车内的可用资源。

| 模块 | 内容 |
|---|---|
| KPI 指标行（6 卡片） | 当前可用火车、我的软件、我的组件、待处理预警、本月新增软件、可下载制品 |
| 当前可用版本火车 | 火车号/起止时间/软件组件数/状态=已发车 |
| 风险提示 | 可用软件中的高危漏洞预警列表 |
| 我的订阅项目 | 项目名/类型（软件/组件）/版本/所属火车/订阅时间/预警状态 |
| 我的可用软件 | 卡片流：名称/版本/评分/漏洞数/许可证/所属火车，支持搜索与按火车筛选、下载/详情 |
| 我的可用组件 | 组件表：名称/版本/组织编号，支持下载 |
| 许可证合规提示 | 可用软件许可证清单 + 合规/关注标记 |
| 快捷入口 | 软件库/组件库/版本火车/使用手册（4 个常用，所有角色通用，位于头部卡片） |
| 最近更新软件 | 时间线 |
| 我的下载记录 | 最近 5 条源码/组件下载记录 |

### 5.3 多组织支持

- 用户可属于一个或多个组织（`orgIds` 数组，`[0]` 为主组织）。
- **单组织用户（绝大多数）**：直接展示所属组织工作台，不出现组织切换器。
- **多组织用户（少数）**：头部显示组织切换下拉，默认主组织，切换后工作台内容联动刷新。
- 角色判断（管理员/普通成员）与组织切换相互独立。

### 5.4 头部信息区（通用）

- 左侧：头像 + 姓名/所属组织 + 角色标签（组织管理员/普通成员）+ 组织切换下拉（仅多组织用户）+ 快捷入口。
- 右侧：演示/会话信息（正式环境为登录用户信息）。

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| 视觉 | 对标平台现有浅色卡片风格，主色沿用 `#da203e`，与 AdminShell 布局一致 |
| 性能 | 图表组件懒加载，页面首屏可交互时间 ≤ 2s |
| 兼容 | 适配 1200px/800px 响应式断点，卡片流降列 |
| 可维护 | 数据源（KPI/列表/图表）统一收敛，预留真实接口替换点 |

## 7. 非目标（本期不做）

- 工作台内嵌侧边栏导航（沿用全局侧边栏）。
- 快捷入口自定义增删排序（本期固定常用入口）。
- 跨组织数据聚合视图（多组织用户通过切换查看）。
- 超级管理员工作台（沿用既有管理入口）。

## 8. 验收标准

1. 用户登录后访问 `/` 自动进入工作台，无路由时不再落至旧首页。
2. 组织管理员与普通成员看到的工作台内容、KPI、操作按角色严格区分。
3. 普通成员工作台全部数据均来自已发车版本火车，无未发车/已下架内容。
4. 单组织用户不显示组织切换器；多组织用户切换组织后 KPI/列表/预警联动刷新。
5. 点击无权限内容时出现「暂无权限查看该软件/组件，请联系组织管理员」提示。
6. 右上角工作台图标在所有页面可用，点击返回工作台。
7. 构建通过（`vite build` 无错误）。
