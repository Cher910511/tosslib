# 软件看护

## 功能概述

软件看护覆盖开源软件从 **需求提出 → 软件治理 → 入库审批 → 结果通知** 的完整闭环。需求提出方（组织管理员）提交软件入库需求，平台分配后由治理负责人执行软件治理并回传成果，最终审核入库，系统自动完成状态回写与结果通知。

本文档按角色视角说明，请根据您的身份查阅对应章节：

- **需求提出方（组织管理员）**：提交软件入库需求反馈，并查看提交数据的状态与原因；
- **治理负责人**：下载待治理清单、回传治理数据、执行软件治理并提交入库审批。

# 视角一：需求提出方（组织管理员）

## 1、提交软件入库需求反馈

进入 **软件入库需求反馈** 页面后，可提交希望引入的开源软件资源需求。页面包含两部分内容：

- **意见反馈**：必填文本，用于描述引入诉求与使用场景；
- **上传 Excel 清单**：上传包含软件条目（软件名称、版本等）的 Excel 文件，平台自动解析出软件条目并生成入库需求清单。

提交后清单进入平台审核流转，等待分配与治理。

## 2、查看我的反馈清单

在个人设置中进入 **我的治理清单** 页面，可查看所提交治理数据的状态。清单字段包括：软件名称、版本、软件地址、治理负责人、提交时间、入库时间、审核状态、原因。

- 状态枚举：待审批、已入库、已拒绝、已作废；
- 已入库的版本号标蓝，可点击跳转软件详情；
- 已拒绝 / 已作废的软件在「原因」列展示具体原因。

# 视角二：治理负责人

## 1、下载待治理清单

进入 **我的待治理清单** 页面，可下载平台分配的待治理清单。点击「下载清单」获取预填模板，包含软件名称、版本、提交人、提交组织等基础信息，在此基础上补充主语言、开源许可证、源码托管地址等治理数据。

![software-care-2](../images/software-care-2.png)

## 2、回传清单

治理负责人维护数据后，上传 Excel / CSV 文件进行回传，系统按以下规则校验：

| 校验项 | 规则 | 不通过处理 |
|---|---|---|
| 必填项 | 名称、版本、主语言、开源许可证、源码托管地址等必填齐全 | 整份文件无法导入，并提示缺失项 |
| 一致性 | 回传数据与下载清单逐条匹配（名称 + 版本） | 整份文件无法导入，并提示不匹配行 |
| 查重 | 与已入库软件比对，重复行自动去除 | 去除并提示“xx 行数据已入库，无需重复治理，已去除” |

![software-care-3](../images/software-care-3.png)

> 任一条校验不通过，则整份文件无法导入；请按提示补齐或修正后重新上传。

校验通过后，回传数据直接解析进软件治理列表，进入正常治理流程。

## 3、软件治理与作废

回传的数据进入 **软件获取** 列表后，正常执行软件治理流程：获取 → 备份 → 扫描 → 评估 → 验收 → 入库。

治理过程中如遇业务调整或评估不达标，可对软件执行**作废**操作：

1. 点击软件行「作废」按钮；
2. 填写作废原因（必填）；
3. 确认后软件从治理列表移除，作废状态及原因保留记录。

![software-care-4](../images/software-care-4.png)

> 作废操作不可恢复；作废后的软件不再进入入库审批流程，但记录会保留在需求提出方的「我的治理清单」中展示。

## 4、提交入库审批

治理成果验收（步骤 4）完成后，可提交入库审核（步骤 5）。提交后软件进入审批流程，最终审核结果将回写状态：

| 状态 | 说明 |
|---|---|
| 待审批 | 已提交入库审核，等待审核 |
| 已入库 | 审核通过，软件正式入库 |
| 已拒绝 | 审核未通过，可在治理日志内查看拒绝原因 |
| 已作废 | 治理过程中作废，不再进入审批流程 |

> 已拒绝的软件支持在治理日志内查看拒绝原因，便于整改后重新提交。

## 常见问题

Q：回传清单时提示校验不通过怎么办？

A：整份文件无法导入。请根据提示定位失败行，补齐必填项或修正与下载清单不一致的数据后，重新上传。

Q：提示“xx 行数据已入库，无需重复治理，已去除”是什么意思？

A：该行软件与已入库软件重复，系统自动去除该行、不再导入，其余数据不受影响。

Q：作废后软件还能恢复吗？

A：不能。作废后软件从治理列表移除，仅保留作废状态与原因记录，不可恢复；如需再次引入，请重新发起需求反馈。

Q：软件被驳回后怎么办？

A：可在治理日志内查看拒绝原因；整改后重新提交入库审核。

Q：我的治理清单中看不到某些提交的数据？

A：请确认当前查看范围：需求提出方仅查看自己提交的数据，治理负责人查看本人负责治理的数据。
