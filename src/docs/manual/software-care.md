# 软件看护

## 功能概述

软件看护覆盖开源软件从 **需求提出 → 清单分配 → 治理结果回传 → 软件治理 → 入库审批 → 结果通知** 的完整闭环。需求提出方（组织管理员）提交软件入库需求，平台分配后由治理负责人按治理模板回传治理结果，再依次完成源码备份、软件评分、治理成果评估与提交入库，最终由平台管理员审批入库，系统自动完成状态回写与结果通知。

本文档按角色视角说明，请根据您的身份查阅对应章节：

- **需求提出方（组织管理员）**：提交软件入库需求反馈，并查看提交数据的状态与原因；
- **治理负责人**：下载治理模板、填写治理结果并回传，完成软件治理后提交入库审批。

> 治理表格共 23 列、全部为必填，各列填写方式与枚举取值详见 **治理表格填写说明**。

## 视角一：需求提出方（组织管理员）

### 1、提交软件入库需求反馈

进入 **软件入库需求反馈** 页面后，可提交希望引入的开源软件资源需求。页面包含两部分内容：

- **意见反馈**：必填文本，用于描述引入诉求与使用场景；
- **上传 Excel 清单**：上传包含软件条目（软件名称、版本等）的 Excel 文件，平台自动解析出软件条目并生成入库需求清单。

提交后清单进入平台审核流转，等待分配与治理。

### 2、查看我的反馈清单

在个人设置中进入 **我的治理清单** 页面，可查看所提交治理数据的状态。清单字段包括：软件名称、版本、软件地址、治理负责人、提交时间、入库时间、审核状态、原因。

- 状态枚举：待审批、已入库、已拒绝、已作废；
- 已入库的版本号标蓝，可点击跳转软件详情；
- 已拒绝 / 已作废的软件在「原因」列展示具体原因。

## 视角二：治理负责人

治理负责人进入 **我的待治理清单** 页面，按「下载模板 → 填写治理结果 → 回传清单 → 软件治理 → 提交入库」的流程完成治理。

### 1、查看说明与下载模板

页面工具栏提供两个入口：

| 入口 | 说明 |
|---|---|
| 治理模板说明 | 打开「治理表格填写说明」，逐列说明填写方式、枚举取值与校验规则 |
| 下载示例模板 | 下载含一条完整示例数据的模板，可参照填写格式 |

> 建议**先查看说明再开始填写治理表格**。

清单列表字段包括：反馈组织、反馈人、清单文件、软件条数、回传状态、成功条数、失败条数、回传时间、操作。

点击行内「下载清单」可获取**预填模板**：已按该清单预填软件名称、软件版本、托管地址，在此基础上补充其余治理结果字段即可。

### 2、填写并回传清单

在预填模板中逐列维护治理结果后，点击行内「回传清单」上传文件（支持 .xlsx / .xls / .csv）。治理表格共 23 列，**所有列均为必填**，确实没有内容的填 `无`。

**国内托管地址目前支持 AtomGit 平台地址**：源码原本就托管在 AtomGit 的，两个地址填同一个 AtomGit 地址；源码仅在 GitHub 等境外仓库的，请先手动上传至 AtomGit，再填写上传后的 AtomGit 地址。

系统按以下规则校验：

| 校验项 | 规则 |
|---|---|
| 必填项 | 23 列全部必填，无内容需填 `无` |
| 枚举取值 | 技术栈分类、集成风险、软件生命力等枚举列须取允许值 |
| 地址格式 | 国内托管地址须为 AtomGit 平台地址 |
| 清单匹配 | 名称 + 版本须落在所选清单内，**多一条、少一条都不允许导入** |
| 查重 | 表格内名称 + 版本不重复，且不与已入库软件重复 |

> **任一条校验不通过，整份文件无法导入**；请按提示修正后重新上传。

回传后清单的「回传状态」按最近一次结果展示：

| 回传状态 | 说明 |
|---|---|
| 待回传 | 已分配但尚未回传文件 |
| 回传中 | 文件已提交，正在校验与导入 |
| 成功 | 校验通过，治理结果已导入源码备份列表 |
| 失败 | 校验未通过，整份未导入，可修正后重传 |

校验未通过时，点击「失败条数」可打开 **回传校验结果** 弹窗，逐行查看失败明细（行号 / 字段 / 失败原因），便于定位并修正。

### 3、软件治理

校验通过后，治理结果进入 **软件治理** 页面，软件从 **源码备份** 开始，依次推进四个步骤：

| 步骤 | 名称 | 主要操作 | 推进到下一步的条件 |
|---|---|---|---|
| 1 | 源码备份 | 校验国内托管地址并拉取源码包，回写备份状态 | 备份状态为「备份成功」 |
| 2 | 软件评分 | 逐条点「评分」打开评分弹窗，完成指标评分 | 评估完成且基线准入通过 |
| 3 | 治理成果评估 | 逐条或批量给出评审意见（评审通过 / 评审不通过） | 评审状态为「评审通过」 |
| 4 | 提交入库 | 提交平台管理员审批，查看审批状态 | — |

治理过程中如遇业务调整或评估不达标，可对软件执行**作废**操作：

1. 点击软件行「作废」按钮；
2. 填写作废原因（必填）；
3. 确认后软件从治理列表移除，作废状态及原因保留记录。

> 作废操作不可恢复；作废后的软件不再进入入库审批流程，但记录会保留在需求提出方的「我的治理清单」中展示。

### 4、提交入库审批

**提交入库**（步骤 4）完成后，可提交平台管理员审批。审批结果将回写状态：

| 状态 | 说明 |
|---|---|
| 待审批 | 已提交入库审批，等待平台管理员审批 |
| 已入库 | 审批通过，软件正式入库 |
| 已拒绝 | 审批未通过，可在治理日志内查看拒绝原因 |
| 已作废 | 治理过程中作废，不再进入审批流程 |

> 已拒绝的软件支持在治理日志内查看拒绝原因，便于整改后重新提交。

## 常见问题

Q：回传清单时提示校验不通过怎么办？

A：整份文件无法导入。点击「失败条数」打开「回传校验结果」弹窗，按行号定位失败行，补齐必填项或修正枚举取值、地址格式后重新上传。

Q：国内托管地址填了 GitHub 地址，为什么回传不通过？

A：国内托管地址目前支持 AtomGit 平台。请先将源码手动上传至 AtomGit，再填写上传后的 AtomGit 地址。

Q：表格里某个字段确实没有内容，能留空吗？

A：不能。23 列全部必填，没有内容的请填 `无`；JSON 类字段（如依赖清单、历史漏洞信息）无内容时可填 `[]` 或 `无`。

Q：提示“清单内软件未在表格中找到”是什么意思？

A：回传文件必须覆盖所选清单的全部软件，少一条即整份不可导入。请用该清单的预填模板补全缺失的软件行后重新上传。

Q：作废后软件还能恢复吗？

A：不能。作废后软件从治理列表移除，仅保留作废状态与原因记录，不可恢复；如需再次引入，请重新发起需求反馈。

Q：软件被驳回后怎么办？

A：可在治理日志内查看拒绝原因；整改后重新提交入库审批。

Q：我的治理清单中看不到某些提交的数据？

A：请确认当前查看范围：需求提出方仅查看自己提交的数据，治理负责人查看本人负责治理的数据。
